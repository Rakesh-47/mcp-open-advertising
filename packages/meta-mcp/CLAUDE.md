# meta-mcp

Platform notes for this package: quirks that are easy to forget when editing it. Repo-wide conventions are in the [root CLAUDE.md](../../CLAUDE.md).

Graph/Marketing API `v26.0`. The hard-coded default field lists (entities, ad accounts, insights) and the insights catalog are checked against v26 field lists vendored from Meta's own `facebook-business-sdk-codegen` specs (`tests/fixtures/graph-v26-spec.json`, generated from the commit it records — regenerate it on a version bump, never hand-edit). Graph rejects a request naming a field its node lacks with `(#100)`, so one stale default breaks every default read. **Unconfirmed (#229):** third-party sources say that from 2026-10-27 three v26 changes apply to every version: `instagram_positions: ["explore"]` errors, `messenger_positions: ["story"]` is silently dropped, and ad sets in the Housing, Employment and Financial special ad categories must set `targeting.targeting_automation.advantage_audience` explicitly. Meta's specs and SDK changelogs neither confirm nor refute this, because positions are untyped strings there. meta-mcp still sends targeting unchanged but warns about all three in response **text only** (#229, `tools/utils/v26-targeting-warnings.ts`): the dry-run and execute responses of `meta_create_entity`, `meta_update_entity`, `meta_bulk_create_entities` and `meta_bulk_update_entities`, and the dry run of `meta_duplicate_entity` (ad sets), add a "Warnings (non-blocking, unconfirmed by Meta)" block. Nothing enters structured content: `validationErrors` and `wouldSucceed` are unchanged, because a governance consumer may treat any entry there as blocking, and a new output field would move the hash. The logic hands the warnings to the formatter through a WeakMap keyed by the result object, which the factory passes through unchanged. Check 3 needs the parent campaign's `special_ad_categories`: the update and duplicate dry runs read it (one rate-limited read, only when `advantage_audience` is unset); creates, bulk writes and every execute path make no read, so there the text says the category was not checked. No shipped example names either placement or puts an ad set in a special ad category (every campaign example sends `special_ad_categories: []`), but most ad-set examples omit `targeting_automation`.
